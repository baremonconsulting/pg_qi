# Pilot administration

Phase 5 records how Baremon qualifies and runs controlled pg_qi pilots.
Use the [current qualification record](current/implementation-qualification.md)
to check the scope, roles and approvals for pilot work.

- [Qualification charter](templates/qualification-charter.md) sets out the
  information needed to define a pilot.
- [Evidence contract](PGQI-5-evidence-contract.md) describes how pilot
  evidence is recorded and validated.
- [Site preflight](PGQI-5-release-site-preflight.md) describes the release
  and environment checks for a proposed site.
- [Customer delta procedure](p5-8-customer-delta.md) describes the approvals
  and evidence needed before a customer pilot.

`INVESTMENT_APPROVED`, `CUSTOMER_PILOT_MANDATE` and `OPERATION_GO` name
decisions in the pilot records. Check the recorded status and scope before
acting on a gate. Keep customer-specific dossiers in the private pilot
workspace. See the [repository boundary](../editions.md#commercial-scope).

For PostgreSQL settings, diagnostics and rollback, use the
[operator cookbook](../phase4/PGQI-4C-operator-cookbook.md).
